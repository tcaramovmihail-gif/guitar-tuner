# Публикация в RuStore

Пошаговая схема выпуска «Гитарного тюнера» в RuStore. Публикация выполняется
вручную владельцем аккаунта: агент готовит артефакт, проверяет подпись и заполняет
чек-лист, но ничего не загружает в магазин без явного подтверждения.

## Что публикуем

| Параметр | Значение |
| --- | --- |
| Название | Гитарный тюнер |
| `applicationId` | `ru.eurovafel.guitartuner` |
| Версия | `0.7.0`, `versionCode 7` |
| minSdk / targetSdk | 26 / 36 |
| Категория | Музыка (или «Музыка и аудио») |
| Цена | Бесплатно, без встроенных покупок |
| Разрешения | микрофон, геолокация, интернет, состояние сети, вибрация |
| Аккаунт | не требуется, основные функции офлайн |

`applicationId` фиксируется при создании карточки и после публикации не меняется.
Если домен `eurovafel.ru` не принадлежит разработчику, лучше подтвердить
`applicationId` до первой загрузки: сменить его после релиза нельзя, а новая
карточка с другим package name начнёт историю заново.

## Шаг 1. Аккаунт разработчика

1. Открыть [RuStore Консоль](https://console.rustore.ru) и войти через VK ID.
2. Заполнить профиль разработчика: тип (физлицо, самозанятый, ИП или юрлицо),
   ИНН, контактные данные, платёжные реквизиты, если они запрашиваются.
3. Приложить документы, которые попросит консоль. Для физлица обычно нужны
   паспортные данные и подтверждение личности; для ИП/юрлица — реквизиты
   и документы организации.
4. Дождаться проверки профиля. До её завершения карточку создать можно, но
   публикация будет недоступна.

Доступы к консоли выдаются по ролям. Для одного разработчика достаточно роли
владельца; помощнику можно выдать отдельный доступ, не передавая пароль.

## Шаг 2. Создание карточки приложения

В консоли: **Приложения → Создать приложение**.

1. Указать название «Гитарный тюнер».
2. Указать package name `ru.eurovafel.guitartuner` — он должен совпадать
   с `applicationId` в `app/build.gradle.kts`.
3. Выбрать категорию и заполнить возрастной рейтинг по анкете.
4. Сохранить черновик. Загрузка файла и описание доступны в карточке.

## Шаг 3. Release-ключ

Ключ создаётся один раз. Потеря ключа ломает обновления: новую версию с другим
ключом магазин не примет как обновление.

```powershell
# из корня проекта
New-Item -ItemType Directory -Force keystore | Out-Null

keytool -genkeypair -v `
  -keystore keystore\guitar-tuner-release.jks `
  -alias guitar-tuner `
  -keyalg RSA -keysize 4096 -validity 10000 `
  -storetype JKS
```

`keytool` входит в JDK. Пароли и alias сохранить в менеджере секретов и сделать
резервную копию `.jks` в защищённом месте.

Рядом с проектом создать `keystore.properties` (файл уже в `.gitignore`):

```properties
storeFile=keystore/guitar-tuner-release.jks
storePassword=ПАРОЛЬ_ХРАНИЛИЩА
keyAlias=guitar-tuner
keyPassword=ПАРОЛЬ_КЛЮЧА
```

Путь в `storeFile` считается от корня проекта. `app/build.gradle.kts` подключает
подпись только при наличии `keystore.properties`; без файла release-сборка
остаётся неподписанной и для магазина не годится.

## Шаг 4. Сборка артефакта

Перед сборкой поднять версию в `app/build.gradle.kts`:

```kotlin
versionCode = 7          // +1 к предыдущей публикации
versionName = "0.7.0"
```

Сборка APK (основной вариант для RuStore):

```powershell
.\gradlew.bat :app:assembleRelease
```

Файл: `app\build\outputs\apk\release\app-release.apk`.

Сборка AAB (если консоль принимает AAB для новой версии):

```powershell
.\gradlew.bat :app:bundleRelease
```

Файл: `app\build\outputs\bundle\release\app-release.aab`.

Проверка подписи APK:

```powershell
$apksigner = "$env:ANDROID_HOME\build-tools\36.0.0\apksigner.bat"
& $apksigner verify --print-certs app\build\outputs\apk\release\app-release.apk
```

В выводе должен быть `CN=...` release-ключа, а не `CN=Android Debug`.
Проверка `versionCode`:

```powershell
$aapt = "$env:ANDROID_HOME\build-tools\36.0.0\aapt2.exe"
& $aapt dump badging app\build\outputs\apk\release\app-release.apk |
  Select-String "package:|sdkVersion|targetSdkVersion"
```

Если на телефоне уже стоит debug-сборка, перед установкой release-APK её нужно
удалить: подписи не совпадают, обновление «поверх» не установится. Удаление
стирает локальные песни и историю карты.

## Шаг 5. Материалы карточки

Подготовить до загрузки:

- **Иконка** 512×512 PNG, непрозрачная, без скруглений и рамок — магазин
  применяет маску сам.
- **Скриншоты** от 3 до 10 штук, портретные, желательно 1080×1920 или снимки
  с реального экрана 1440×3120. Показать тюнер, песню с аккордами, метроном,
  настройки и карту.
- **Название** до 50 символов: «Гитарный тюнер».
- **Краткое описание** до 80 символов: «Тюнер, песенник с аккордами и метроном.
  Работает офлайн».
- **Полное описание** до 4000 символов: что умеет, для кого, что не требует
  аккаунта, какие разрешения и зачем.
- **Что нового** для версии: 3–7 пунктов из `artifacts/release/notes-0.7.0.md`.
- **Ссылка на политику конфиденциальности** — публичный URL, не файл в APK.
- **Контакты разработчика** для карточки и поддержки.

Скриншоты снимаются с рабочей сборки. На телефоне:

```powershell
$d = "adb-R5CYA2CZL7P-qFUth1._adb-tls-connect._tcp"
adb -s $d shell screencap -p /sdcard/rustore-01.png
adb -s $d pull /sdcard/rustore-01.png artifacts\rustore\rustore-01.png
```

## Шаг 6. Политика конфиденциальности и разрешения

RuStore требует политику для приложений, которые запрашивают доступ к данным
пользователя. Черновик текста — `docs/PRIVACY.md`. Перед публикацией:

1. Заполнить в политике имя оператора и контактный e-mail.
2. Опубликовать документ по постоянному публичному URL (сайт, страница-визитка,
   статический хостинг). Ссылка не должна вести на файл внутри приложения.
3. Вставить URL в карточку RuStore.

Декларация разрешений в карточке:

| Разрешение | Зачем |
| --- | --- |
| `RECORD_AUDIO` | определение частоты струны; звук обрабатывается на устройстве и не передаётся |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | отметка места игры на карте; координаты хранятся только на телефоне |
| `INTERNET`, `ACCESS_NETWORK_STATE` | поиск песен в каталогах и отправка отзыва |
| `VIBRATE` | короткий отклик при попадании в ноту |

Если консоль просит обоснование каждого опасного разрешения, использовать
формулировки из таблицы. Для геолокации указать, что функция необязательна
и отключается отказом в доступе.

## Шаг 7. Загрузка и отправка на модерацию

1. В карточке открыть раздел загрузки файла и выбрать `app-release.apk`.
2. Дождаться проверки файла: консоль покажет `versionCode`, `versionName`,
   размер и подпись.
3. Заполнить описание, скриншоты, возрастной рейтинг и политику.
4. Проверить, что в карточке нет ссылок на сторонние магазины и APK-хостинги.
5. Нажать «Отправить на модерацию».

Если консоль предлагает загрузить AAB, а не APK, использовать
`app-release.aab`. Для AAB магазин может подписывать сборку своим ключом —
актуальный порядок показывает сама консоль при загрузке.

## Шаг 8. Модерация

Обычно проверка занимает от одного до трёх рабочих дней; сложные случаи дольше.
Частые причины отказа:

- приложение падает при запуске или на одном из экранов;
- описание не совпадает с фактическими функциями;
- нет политики конфиденциальности или она недоступна по ссылке;
- не обоснованы микрофон и геолокация;
- скриншоты не соответствуют приложению;
- в интерфейсе есть ссылки на сторонние магазины или скачивание APK.

При отказе консоль показывает причину. Исправить, поднять `versionCode`,
собрать заново и отправить новую версию. Переписка с модерацией ведётся
в карточке.

## Шаг 9. Публикация и обновления

После одобрения нажать «Опубликовать». Приложение появится в поиске RuStore
в течение нескольких часов.

Для следующего обновления:

1. Внести изменения и поднять `versionCode` (обязательно) и `versionName`.
2. Прогнать JVM-тесты и `:app:assembleDebug`.
3. Собрать `:app:assembleRelease` с тем же ключом.
4. Загрузить новый файл в существующую карточку, заполнить «Что нового».
5. Отправить на модерацию.

Ключ подписи не меняется никогда. Если ключ утерян, обновить приложение в рамках
той же карточки не получится — потребуется новая публикация с другим
`applicationId`.

## Чек-лист перед отправкой

- [ ] Профиль разработчика подтверждён.
- [ ] `applicationId` окончательный: `ru.eurovafel.guitartuner`.
- [ ] `versionCode` больше предыдущего опубликованного.
- [ ] Release-ключ создан, `keystore.properties` и `.jks` вне git.
- [ ] `apksigner verify` показывает release-сертификат.
- [ ] APK/AAB устанавливается на чистое устройство и запускается.
- [ ] Тюнер, песни, метроном и карта проверены на телефоне.
- [ ] Иконка 512×512 и 3–10 скриншотов готовы.
- [ ] Название, краткое и полное описание заполнены.
- [ ] Политика конфиденциальности опубликована по публичному URL.
- [ ] Разрешения объяснены в карточке.
- [ ] В приложении и описании нет ссылок на сторонние магазины и APK-хостинги.
- [ ] Тестовый отзыв отправляется, версия на экране «Отзыв» совпадает.

## Ограничения текущей итерации

- FormSubmit требует активации формы по письму владельца: без активации отзывы
  на почту не доходят. Проверить до публикации.
- Дублирование отзыва в Telegram выключено, пока в `local.properties` нет
  `telegram.bot.token` и `telegram.chat.id`.
- Debug-APK версии 0.7.0 подписан отладочным ключом и для RuStore не подходит.
- Загрузка в магазин, создание ключа и публикация выполняются только вручную
  владельцем аккаунта.
